# `data/` — All project data

This folder centralises **all** the data used in the thesis. It used to be scattered
across several folders (`datasets/`, `log_regression/datasets/`); now everything lives
here, in three subfolders with a clear meaning.

## `raw/` — Raw data (original source)
Files exactly as downloaded/received, **before** any cleaning:
- `coca_cultivation.csv` + `coca_cultivation/` — coca cultivation data (UNODC-SIMCI), cleaned shapefile.
- `national_natural_parks/` — National Natural Parks shapefile (RUNAP).
- `roads/` — road network shapefile.

These files were used to create the "assets" (layers) that live in Google Earth Engine
(project `col-amazon-fire-susceptibility`).

## `processed/` — Processed data (intermediate tables)
Tables already computed from Google Earth Engine, ready to plot or analyse:
- `burned_df.csv` — annual burned area (target).
- `climate_df.csv` — dry-season climate variables by year.
- `coca_df.csv` — coca hectares by year.
- `lulc_area_df.csv` — area by land-cover class (LULC) by year.
- `pixel_year_df.csv` — pixel-year table used in exploratory analyses.

These files are generated by the `eda/` notebooks (if they don't exist, they're
recomputed from Earth Engine and saved here automatically, so slow calculations don't
have to be repeated).

## `model_dataset/` — The frozen dataset for Machine Learning
This is **the official dataset** used by ALL models (logistic regression, Random Forest,
and XGBoost). It's called "frozen" because once created it shouldn't be modified — this
guarantees every model is compared on exactly the same data.

- `pixel_year_full.csv` — full table before class balancing (83,184 rows, 2.5% fires).
- `model_dataset.csv` — **the final dataset** used to train/evaluate (6,231 rows,
  balanced 1:2 fire:no-fire). Contains the 9 predictor variables + `burned` (the target
  variable) + `lon`, `lat`, `year` (metadata, NOT predictors).

This dataset is built by
[`model/logistic_regression/baseline_comparison.ipynb`](../model/logistic_regression/baseline_comparison.ipynb)
the first time it runs; after that it's simply loaded from here. Note: a later
sensitivity analysis ([`tuning/v3/`](../tuning/v3/README.md)) found a 1:1 ratio performs
better than this frozen dataset's 1:2 ratio, and the final deployed model
([`tuning/v4/`](../tuning/v4/README.md), [`outputs/probability_map/`](../outputs/probability_map/README.md))
uses a different, 1:1 ring-sampled dataset built directly from `pixel_year_full.csv` — this
frozen `model_dataset.csv` remains the baseline/comparison dataset used by the early
models, not the one behind the final map.
